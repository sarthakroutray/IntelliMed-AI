# Taste
- Prefers additive, backward-compatible evolution: freeze existing API contracts/behavior exactly and add new functionality under a new version/namespace rather than rewriting. Confidence: 0.9
- Prefers modular pipelines with separable stages and standalone pure-function modules, reusing existing shared infrastructure instead of duplicating wrappers or embedding logic inline. Confidence: 0.85
- Requires end-to-end auditability for AI-derived outputs, preserving traceability back to exact source values/locations with no black-box outputs. Confidence: 0.9
- Enforces strict separation between extraction and interpretation: ML/OCR stages do faithful extraction only and must never emit abnormal flags, patterns, or judgments; all interpretation lives in deterministic, unit-testable rule logic. Confidence: 0.9
- Keeps decision rules in external editable config files rather than hardcoded logic, leaving clearly-marked placeholders when content requires domain-expert review. Confidence: 0.85
- Frames all AI output as assistive context for expert human review only, never as diagnosis or clinical recommendation, using non-diagnostic phrasing and explicit review warnings. Confidence: 0.9
- Prefers explicit verification over silent workarounds: verify system/deployment dependencies before integrating, keep training/fine-tuning pipelines out of the request path, and flag blockers or data requirements back instead of substituting libraries or proceeding inline. Confidence: 0.85
- Requires tests for deterministic logic at minimum plus regression verification of existing behavior — run existing tests if present, otherwise note gap and do manual verification before changing anything. Confidence: 0.85
- Empirically probes third-party library APIs before coding against them: generates realistic sample inputs and runs real end-to-end conversions to inspect actual output structure, rather than trusting docs or function signatures. Confidence: 0.85
- Prefers runtime tunables and feature toggles exposed as environment variables with sensible defaults (e.g. LAB_* thresholds, backend options, timeouts) instead of hardcoded constants or ad-hoc arguments. Confidence: 0.75
- Prefers graceful fallback chains in pipelines where every degradation (missing dependency, scanned/image-only input, insufficient extraction) is surfaced as an explicitly recorded warning — behavior may downgrade but never silently. Confidence: 0.8
- Verifies new work with a full end-to-end smoke run on a synthetic fixture, not just unit tests — passing unit tests are not treated as sufficient; when the smoke run exposes integration bugs, enumerate them, fix, and re-run before declaring done (smoke test caught 3 real parsing bugs that 19 passing unit tests missed). Confidence: 0.8
- Writes pure functions that never mutate caller inputs: deep-copy before annotating and add dedicated tests asserting the original object is unchanged. Confidence: 0.7
- Keeps packaging/deployment configs in sync with code changes: new dependencies go into requirements.txt, every new env var is documented in .env.example with usage notes, and new services are wired into docker-compose. Confidence: 0.7
- Wants environment/config wiring audited across every component at once and validated against what the code actually reads — cross-check that no required variable is missing, that example/docs values match real client behavior (e.g. no base URL that double-appends the API prefix), and that advertised-but-unwired or inert variables are corrected or clearly marked reserved. Confidence: 0.7
- Imports heavy or optional dependencies lazily at the point of use so core modules and pure logic stay lightweight in minimal contexts. Confidence: 0.6
- Prefers measurement-gated simplicity over premature optimization: start with the simplest resident/naive resource strategy and add complex scheduling or swapping only after real-device measurements prove pressure, including A/B comparison of load strategies for perceived responsiveness. Confidence: 0.85
- Requires report-back checkpoints for open architectural choices: spike competing options against real artifacts and report findings for human sign-off before full integration, never silently committing; when ambiguous, proceed with a sensible default while explicitly flagging the tradeoff. Confidence: 0.85
- Prefers offline-first edge sync: persist results locally with explicit pending/synced/failed status, sync structured outputs only (never raw inputs) tagged with source provenance, serialize heavy work through a simple queue to avoid overlapping contention, and retry when connectivity resumes. Confidence: 0.8
- Positions SLM as OCR-text standardizer that transforms raw OCR text into structured JSON/summary context, not as open-ended generator or diagnostician. Confidence: 0.8
- Wants inference to run where the device/data is: mobile apps do ML inference entirely on-device and upload only structured results, while the heavier server-side SLM is reserved for the web path — no server-side inference for app-sourced data. Confidence: 0.8
- Expects prior work to be recovered via git history/branches/stash/reflog before reporting a gap — explicitly asks to check previous git when an artifact appears missing. Confidence: 0.75
